## 修复与复测

- **工程与目标。** 在 Windows 版 VS Code 中分别用中文和英文打开空目录，确认页面说明缺少的文件，两个“浏览”按钮各有独立名称。含应用构建文件时可以配置。输入两行定义，往返切换 CMake 和 west 后，两行均恢复。更换构建目录后得到独立的草稿。
- **构建结果。** 复测发现 CMake 首次配置失败也会写缓存。构建入口现在同时核对缓存的应用和生成阶段的目标目录清单。测试覆盖只有缓存、已生成工程、源目录不匹配三种情况。在界面用本地 SDK 和模块配置并编译 HC32F4A0 的 `hello_world`，确认生成 `zephyr/zephyr.elf`。
- **布局。** 统一两个构建方式的选中态、工程选择器样式和目录行。工作区内的路径使用简短名称，悬停可查完整路径。移除空构建页重复的“添加构建 / 添加测试”。在中英文、深浅色主题的 790 × 718 编辑视口检查了工程页；短页整体无需滚动。清单用 2 项和 80 项分别检查，长清单上下独立滚动。
- **模块操作。** 实际读取测试工作区的 west 清单，搜索 `cms` 并勾选 `cmsis_6`，随后筛选 `hstm32`，已选模块和目标版本继续显示。该操作可以离线练习。
- **代码。** SDK 和本地二进制组件共用流式 SHA-256；构建方式、草稿和清单筛选通过同一组页面状态读写方法保存。工程和构建选择器共用带无障碍名称的模板。
- **教学。** [中文手册](../../resources/workbench.zh-cn.md)和[英文手册](../../resources/workbench.md)各附两段本地操作动图，分别演示草稿恢复、筛选与勾选模块。

## 安装包验证

Windows 扩展宿主单元测试 549 项通过，22 项标为 pending；west 的 Python 测试 6 项通过。TypeScript 编译与 ESLint 通过。从 VSIX 在独立中英文窗口启动扩展，通过工程页打开对应语言的手册，各自的两幅 GIF 均成功解码。英文 458 像素、中文 456 像素宽的编辑区内，目录按钮和构建操作均在可见宽度内。

Windows 是本轮交互复测平台。Linux、macOS 和实体板烧录、调试留待相应环境验证。
